# Google Developer Documentation Style Guide (Full)

> Based on the Google Developer Documentation Style Guide.
> Use this for comprehensive technical writing standards.

## General Principles
- Be concise. Use as few words as possible.
- Be specific. Avoid vague words like "some" or "many."
- Use second person ("you") for instructions.
- Use active voice.
- Use present tense.

## Formatting
- Use sentence case for headings.
- Use code font for code elements.
- Use bold for UI elements.
- Use italics sparingly.

## Writing Style
- Avoid future tense ("will") unless necessary.
- Avoid first person ("I", "we") unless necessary.
- Write inclusive documentation.
- Use accessible language.

## Code Examples
- Use descriptive variable names.
- Include comments for complex logic.
- Follow language-specific conventions.
- Test all code samples.

## Links and Cross-References
- Use descriptive link text.
- Avoid "click here" or "this link."
- Verify all external links.

## Numbers and Units
- Use numerals for numbers 10 and above.
- Spell out numbers one through nine.
- Use consistent units.

## Lists
- Use parallel structure.
- Start each item with a capital letter.
- End with periods for complete sentences.

## Voice and Tone
- Helpful and humble.
- Expert but not condescending.
- Friendly but not overly casual.
