# Google Developer Documentation Style Guide (Light)

> Simplified version of the Google style guide.
> Use this for quick reference without overwhelming detail.

## Quick Rules
- **Be concise**: Fewer words = better.
- **Active voice**: "The system returns an error" not "An error is returned."
- **Second person**: "Click the button" not "The user clicks the button."
- **Present tense**: "The API returns" not "The API will return."
- **Sentence case headings**: "Getting started" not "Getting Started"
- **Code font for code**: `functionName()` not "functionName()"

## Avoid
- Future tense ("will")
- First person ("I", "we")
- Vague words ("some", "many", "very")
- "Click here" links
- "Simply", "just", "obviously"

## Code Examples
- Descriptive variable names
- Tested samples
- Comments for complex logic

## Voice
- Helpful and humble
- Expert but friendly
- Never condescending
